## 0. 定位（用户原话，这条决定其余一切）

> "我们现在这种相当于用户在自己搭建一个快捷的 TB 了，得到的肯定是**所搭即所得**"

连接表**就是一个快速搭起来的 testbench**。用户装一个电路（EM 块 + PKG 块 + 中间元件），
工具报告**这个装好的电路量出来是什么**。不是"提取原语再与基线比较"。

**交付物：绝对值（甲）为主。** 差值（乙）是选项，而且**已经存在**——freeze-as-trace：
不接封装 Calculate 一次并冻住，接上封装再 Calculate，两行并排。只需文档化，
最多加一个一键入口。评审建议"交付物应当是 delta"，被用户否掉，理由正当。

**但这个定位提高了要求，没有降低。** 承诺"所搭即所得"，则工具的首要职责变成
**让"所搭"本身无歧义地可见** —— 因为"所搭 ≠ 你以为的所搭"时，"所得"就是精确的错答案。
今晚实测到的两个坑都属于这一类，且都无声：

* `23,24,25 lumped_between 10` —— 以为一个电感，实际三个并联（实测 3.333 fH vs 10.000）
* `block_diag` 焊死参考节点 —— 以为封装地接进去了，实际它不在电路里
  （实测接地/开路/1 nH 逐位相同）

⟹ 自动检验、行模板、节点显式化，在这个定位下**不是锦上添花，是兑现承诺的必要条件**。

用户用网表（节点 + 器件）说话，不是"逐端口端接清单"。本体论以前者为准。

排期：等 attribution-window-polish 落地后开工（它正在改 `pkg_rlc/frontend/app.py` / `CLAUDE.md` / `docs/`，现在动会冲突）。

## 1. 用户要什么

一份是自己 EM 提的 snp，一份是 PKG 的 snp。要看**EM 结构挂在非理想 PKG 上之后，参数变成什么样**。

顺带一条 UX：连接表现在不管什么类型都是同样两个空格。多个 pin 短接在一起时，
自然的心智是**一个空格、把要短接的 PIN 填进去**，而不是被迫拆成"从"和"到"。

## 2. 数学：这是现有管线，不是新东西

两份文件 A（Na 口）和 B（Nb 口），把 A 的某些口接到 B 的某些口上。

```
Y_combined = block_diag(Y_A, Y_B)        (Na+Nb) x (Na+Nb)
端口重编号：A 的口 1..Na，B 的口 Na+1..Na+Nb
每一条跨文件连接 = 一个 ShortPair(a_i, Na + b_i)
```

然后**原封不动交给 `compute_z_matrix`**：短接合并（Union-Find）→ 接地删行列 →
Schur 消去 → 探针收缩。一步都不用改。

⟹ 所有既有模式、Mode 5 DSL、Mode 6 互耦、归因引擎、冷启动筛查，
**在组合网络上自动全部可用**。

### ⚠ 前置条件：block_diag 把两个参考节点焊死了（实测，本节原先说反了）

n×n 的 Touchstone Y 是**消去了自身参考节点之后**的矩阵。所以
`block_diag(Y_A, Y_B)` 不是"把两个网络并排放着"，而是
**把 A 的参考和 B 的参考用零阻抗焊在一起**。

实测（2 nH 线圈、100 pH 封装走线、100 pH 封装地引线，5.205 GHz）：

```
A  die 回流是一个端口，接到封装地焊盘上      L_eff = 2.2239 nH
B  die 回流就是 EM 的参考节点（片上常规做法）:
     封装地焊盘 接地                        L_eff = 2.1216 nH
     封装地焊盘 开路                        L_eff = 2.1216 nH
     封装地焊盘 串 1 nH                     L_eff = 2.1216 nH
   三者逐位相同，spread = 0.000e+00
```

⟹ **情形 B 下封装的整个地网络是不可达的**，接地/开路/1 nH 给出同一个数，
而且没有任何东西会提示这件事发生过。这恰恰就是 6 dB 问题的形态，
从一扇本文档原本宣传为"出口"的门里又走了回来。

**所以组合分析只在一种配置下真正解决问题：EM 文件必须把回流路径作为端口引出来。**
这是**前置条件，不是警告**：工具必须能判断 die 侧文件有没有可信的回流端口，
判断不了就说出来。原先写的"真实 PKG 的地网络就在文件里，这正是 6 dB 分歧的正解"
是错的，已删除。

### 前置条件满足时，白送的部分

组合之后，PKG 的每一个 pin 就是一个普通端口。于是：

- **冷启动筛查直接回答"我这个 EM 参数对 PKG 的哪些 pin 敏感"**
- **归因分解给出"这个 M 里 PKG 哪几个 pin 各贡献多少、符号如何"**

而且归因层正好是**判断自己处在哪种配置**的工具：如果组合后的归因报告说
封装地元件的贡献是 0.000，那就是情形 B，组合什么也没告诉你。
**组合应当为归因层供料，而不是取代它。**

## 3. 真正的工作量在这三处，不在数学

### 3a. 频率栅格（最大的风险）

EM 文件和 PKG 文件的频点几乎不会一样。必须对齐。

- 默认：取两者频率**跨度的交集**，在**较细的那个栅格**上插值
- **拒绝外推**。超出任一文件跨度的频点直接不算，并说明砍掉了多少
- 插值对象：S 的 Re/Im 线性插值是最低标准；栅格差得远时要说
- 插值会破坏无源性 —— 插完做一次 `max|S|` 检查，超了就报（`data_notes` 已有这条）
- 两份文件的 `Z0` 不同必须重归一化，不能默默当成一样

### 3b. 端口命名空间

两份文件之后 "port 5" 是歧义的。需要 `A:5` / `PKG:12` 这种带前缀的写法。
`parse_port_range` 要认前缀；`port_roles` / `Ports & Roles` 窗口要显示来源文件。

### 3c. DSL 扩展（与现有行式语法同构）

```
load  EM  = coil_emx.s16p
load  PKG = package.s60p

EM:1  connect PKG:12
EM:2  connect PKG:13
PKG:40,41,42  ground
EM:3  signal vco +
EM:4  signal vco -
```

`connect` 就是跨文件的 `short_to`，走同一条 Union-Find。

## 4. 连接表的自然化（用户的第二点，他是对的）

现在每一行都是固定的 `Port | Kind | To | R | L | C | ✕`，
但**需要几个端口字段是由 Kind 决定的**：

| Kind | 端口字段 | 说明 |
|---|---|---|
| `ground` / `vdd` / `open` | **1 个** | "To" 完全无意义，现在却占着一个空格 |
| `short` | **1 个** | `5,6,7,8` —— 一个组没有天然的"从/到"，拆成两格是人为的 |
| `rlc_gnd` | 1 个 + RLC | |
| `rlc_between` | **2 个** + RLC | 二端元件真的有两端，这里两格是对的 |
| `connect`（新） | **2 个** | `EM:1` / `PKG:12` |

改法：Kind 决定第二个端口格是否可用；`short` 时把两格**并成一个宽格**。

**不加列**（CLAUDE.md 记录的预算是 405 px 表 / 431 px 视口，只剩 13 px 余量），
只是把已有的像素重新分配 —— 合并两格不增加宽度。

DSL 无需改动：单格里的 `5,6,7,8` 序列化成 `5 short_to 6,7,8`，
`parse_port_range` 两边本来就都吃范围。

## 4b. 缺失的概念：合并节点要能被称呼（用户举例钓出来的）

用户的例子：EM 的 23/24/25 短接，再经一个 10 fH 电感接到 PKG:10。

**实测**（5 端口纯阻性网络，任何 Im(Z) 只能来自电感）：

```
1     lumped_between 4 L=10f   先短接、元件挂合并节点  :  10.000 fH   ✓
1,2,3 lumped_between 4 L=10f   用户会自然写出的写法    :   3.333 fH   ✗  (3 个并联)
inert_lumped_messages 的反应：什么也没说
```

`lumped_between` 左边吃范围 = 每个端口各出一个元件。这个语义本身是对的
（`5-12 lumped_to_gnd R=50` 表示每个球各一个 50 Ω），但套在
「先短接再接一个元件」上就是静默 3 倍错误。

### 补法一：给短接组命名

```
EM:23,24,25   short  as coil_tap
coil_tap      lumped_between  PKG:10  L=10f
```

短接行只需要**一个**端口格（§4 已定），省下的那格正好放名字 —— **不加列**。
其他行的端口格接受这个名字。这才是用户脑子里的模型：
「这三个是同一个点，从这个点接一个电感出去」。

### 补法二：并联回显，不拒绝

N 个元件并联在同一对合并节点之间有时是对的（N 个 bump 并联）。不能拒绝，
但验证条必须回显**等效值**：

```
✓ node{23,24,25} → PKG:10 : 3 × 10 fH 并联 = 3.33 fH
```

想要一个的人立刻看见。放在 `inert_lumped_messages` 旁边，同一类检查。

### 补法三：`connect` 就是跨文件的 `lumped_between`

用户的例子是 EM 节点 →(元件)→ PKG 端口，不只是端口对端口短接。
所以短接是 `R=0` 的特例，**一个原语，不做两套**。

## 5b. 今晚全部实测数字（工作流任务书直接从这里取，不要从记忆取）

助手自己跑出来的（脚本在 scratchpad）：

| 发现 | 数字 | 结论 |
|---|---|---|
| `block_diag` 焊死参考节点 | die 回流是端口 2.2239 nH；die 回流是 EM 参考时，封装地球 接地/开路/1nH = **2.1216 nH 逐位相同，spread 0.000e+00** | 组合的前置条件，不是警告 |
| 归因在组合网上失效 | `Ybase` EM-PKG 交叉块 = **0.000e+00**（精确块对角）；封装地球贡献 **恰好 0**，而**对账残差 6.49e-15** | "白送杀手锏"是坏的；跨文件连接必须进基线 |
| 合并节点的 3 倍坑 | 先短接后 `1 lumped_between 4 L=10f` = **10.000 fH ✓**；`1,2,3 lumped_between 4 L=10f` = **3.333 fH ✗**，比值 3.000；`inert_lumped_messages` 沉默 | 用成员端口引用节点**今天就能用**；缺的是拒绝和顺手的手势 |
| `:` 语法冲突 | `parse_port_range('PKG:12')` → RAISES "Range must be start:step:stop"；`PKG:40:1:50` 同 | 文件分隔符不能用 `:` |
| 短接不能当元件 | `y_series_rlc(0,0,inf)` = **inf+nanj** | 一套语法、两个原语 |
| 现有 hint 没盖住这个坑 | hint 提到 `rlc_gnd` 的左侧范围，**没提 `rlc_between` 的** | "再加一行提示"是死路 |
| 引擎分批失效 | `_freq_batch`: 16→64, 60→4, 76→2, **153→1, 316→1** | "一步都不用改"对数学成立，对产品不成立 |
| Z0 重归一化是伪工作量 | `max\|Y(z0=50) − Y(z0=75)\|` = **1.049e-17** | 从工作清单删除 |
| 独立地引线 vs 共享回流 | 4 球各 1 nH vs 短接后共用 1 nH：**9.60 dB**；两种写法描述同一网络时 **0.000 dB** | 已在归因引擎中修掉 |

评审给出、助手**未独立复现**（任务书里要标注）：

- 316 端口 × 1601 点一次扫描 **173 s**；76→316 端口是 72× flops
- `reduce_snp.py` 预约简：一次性 66 ms/频点，之后每次改规格 0.07 ms/频点，
  对比每次全解 84 ms/频点 → **编辑循环 1226×**
- 插值**不可能**破坏无源性（`{S: σ_max ≤ 1}` 是凸集，实测 max σ = 0.999999900000）
  ⟹ "插值后重查 max|S|" 结构上永不触发，删掉；改查**逐区间相位步进** `Δφ = 2π·Δf·τ`
  （<20° 是噪声，>60° 是错答案），以及它造成的**假损耗**（10 mm 走线 1 GHz 步进 = −0.192 dB）
- `max|S|` 本来就不是无源性检验（反例：所有非对角 0.6，`max|S_ij|=0.6` 而 `σ_max=1.80`）
- 连接表惰性单元格：`ground` 行 **195 px / 48%**、`short` 行 123 px / 30%
- 两文件列宽实测：一个文件列 451 px、两个 497 px、加宽 Port/To 461 px —— **全部超 431 px 视口**；
  `EM:23,24,25` = 70 px 塞不进 55 px 可见区 ⟹ **默认作用域 + 短别名**是唯一免费选项
- `cond(block_diag(A,B)) ≥ max(cond A, cond B)` 恒成立；实测 2.475e16 + 6.1 → 4.645e16
- `TraceConfig.file_label` 是单个 `str`，被 `_config_signature` / `_snapshot_row` /
  `port_descriptor` / `_replot_from_cache` / `_on_remove_file` / `_roles_header` /

## 6. 已定的假设（不阻塞，先按这个做）

1. **端口对应关系由用户给**，脚本绝不按名字或顺序猜 —— 沿用既有原则
2. **频率默认取交集 + 细栅格插值，拒绝外推**，并报告砍掉了多少
3. **两文件以上**：先只做两文件，但 API 从一开始就写成 N 文件（`block_diag` 本来就是 N 元的）
4. **`Z0` 不一致就重归一化**，并在文件摘要里写明
